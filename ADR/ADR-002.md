# [ADR-002] 분기 판정 시점

- **작성일자:** 2026-10-29
- **작성자 / 리뷰어:** 한대규/장병옥, 정현재
- **상태:** 승인됨 (Accepted)
- **영향 범위:** PC 선택, 분기 비교, 파이프라인 플러시 및 분기 데이터 의존성

---

### 1. 배경 및 결정

분기 조건을 파이프라인의 어느 단계에서 판정하느냐에 따라 잘못된 경로에서 가져온 명령어 수와 분기 피연산자를 준비하는 비용이 달라진다. 분기를 일찍 판정하면 잘못 가져온 명령어를 줄일 수 있지만, 비교 경로를 앞당기고 데이터 의존성 처리를 복잡하게 할 수 있다.

**선택안:** 분기와 점프를 EX 단계에서 판정하고, taken이면 더 어린 명령어를 무효화한 뒤 목표 주소로 전환한다. 이는 낮은 설계 복잡도와 명확한 EX 피연산자 포워딩을 우선하는 선택이다.

### 2. 대안 비교

| 판정 시점 | 잘못 가져온 명령어 수(기본 5단계 예시) | 장점 | 비용 및 주의점 |
| :--- | :--- | :--- | :--- |
| IF 예측 | 예측 성공 시 0; 실패 시 예측 깊이에 따름 | 예측이 맞으면 제어 지연을 숨길 수 있음 | 예측기·BTB·복구 제어 필요; 실제 조건 판정 자체를 IF에서 수행하는 방식과 구분 필요 |
| ID | 보통 1개 | EX 판정보다 플러시 대상과 분기 지연 감소 | ID 비교기 및 피연산자 우회/스톨 필요; 직전 ALU·load 결과 의존성 처리 복잡 |
| EX (선택) | 보통 2개 | 기존 EX 연산 피연산자 및 포워딩 경로 활용 가능 | taken 분기에서 IF/ID와 ID/EX 무효화; 분기 페널티 증가 |
| MEM 이후 | 보통 3개 이상 | 판정 로직을 뒤 단계에 둘 수 있음 | 잘못된 경로 명령과 플러시 비용 증가; 일반적인 단순 파이프라인에서 이점이 적음 |

### 3. 타이밍 예시

표기: `B`는 분기, `s1/s2`는 순차 경로의 젊은 명령어, `T`는 분기 목표 명령어, `×`는 무효화된 명령어다. taken 분기이며 데이터 해저드가 없다고 가정한다.

#### 대안 A: ID 단계에서 판정

| 명령어 \ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| B | IF | ID 판정 | EX | MEM | WB | |
| s1 | | IF | × | | | |
| T | | | IF | ID | EX | MEM |

ID에서 조건과 목표를 계산할 수 있으면 C2 종료 시 PC를 바꾸고, IF의 순차 명령 하나만 무효화한다. 다만 분기 비교 피연산자가 아직 준비되지 않았다면 추가 포워딩 또는 스톨이 필요하다.

#### 대안 B: EX 단계에서 판정 (선택)

| 명령어 \ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 | C7 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| B | IF | ID | EX 판정 | MEM | WB | | |
| s1 | | IF | ID | × | | | |
| s2 | | | IF | × | | | |
| T | | | | IF | ID | EX | MEM |

EX에서 taken을 판정하면 순차 경로의 두 명령이 파이프라인에 들어와 있으므로 둘을 무효화한다. 목표 명령의 인출은 다음 사이클부터 시작한다. 구현의 인출 메모리 지연 등에 따라 실제 관찰 시점은 달라질 수 있다.

#### 대안 C: 예측 후 판정

| 상황 | 분기 예측 | 분기 결과 확정 | 복구 동작 |
| :--- | :--- | :--- | :--- |
| 예측 성공 | IF에서 순차 또는 목표 주소 선택 | 선택한 판정 단계에서 조건 확정 | 잘못된 경로 명령이 없으면 플러시 불필요 |
| 예측 실패 | 예측 경로에서 인출 계속 | 선택한 판정 단계에서 불일치 확인 | 예측 경로 명령을 무효화하고 올바른 주소로 전환 |

예측 방식은 정적 예측(예: 항상 not-taken)부터 동적 예측 및 BTB까지 선택지가 있다. 이 ADR의 선택에는 예측기를 포함하지 않는다.

#### 대안 C 상세 예: IF에서 taken 예측, EX에서 확인

| 명령어 \\ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| B | IF (taken 예측) | ID | EX 확인 | MEM | WB | |
| T | | IF | ID | EX | MEM | WB |
| 순차 경로 명령 | | | | | | |

IF에서 목표 주소를 제공할 예측기/BTB가 있고 예측이 맞으면, 확인은 EX에서 하더라도 잘못된 경로 명령을 파이프라인에 넣지 않을 수 있다. 예측 실패 시에는 EX 판정 기준의 복구와 플러시가 필요하다. 예측기 없는 단순 IF 단계 판정은 명령어를 해독하기 전 실제 분기 조건을 알 수 없으므로 이 선택지와 동일하지 않다.
### 4. 결과 및 후속 결정

- taken 분기·점프에서 순차 경로의 IF/ID 및 ID/EX 명령을 무효화한다. Load-use 정지 조건도 동시에 요청되면 분기 redirect/flush를 우선 적용한다: PC는 분기 목표로 갱신하고 IF/ID와 ID/EX를 플러시하며, load-use 정지는 적용하지 않는다.
- 분기 피연산자는 EX 단계에서 포워딩된 값을 사용한다. load 직후 분기처럼 결과가 늦게 준비되는 의존성은 해저드 정책에 따른다.
- 별도 결정이 필요한 항목: 분기 예측 도입 여부, 예외·인터럽트와 분기 플러시 우선순위, 목표 주소 계산 방식.
- 페널티는 위 기본 파이프라인 예시의 사이클 수이며, 실제 메모리 응답 및 구현 조건으로 확정한다.
