# [ADR-007] CSR 명령어의 데이터 의존성(RAW) 및 피연산자 전달 경로

- **작성일자:** 2026-10-30
- **작성자 / 리뷰어:** 한대규/장병옥, 정현재
- **상태:** 승인됨 (Accepted)
- **영향 범위:** EX 단계 피연산자 우회 선택, CSR 소스 전달 레지스터, Load-use 및 CSR-use 해저드 제어

---

### 1. 배경 및 문제 정의

ADR-006에서 CSR 연산과 상태 갱신을 WB 단계에서 수행하기로 결정함에 따라, 일반 레지스터(GPR)와 CSR 명령어 사이의 데이터 의존성(RAW 해저드)은 두 가지 방향으로 나타난다.

1. **CSR이 RAW의 소비자(Consumer)인 경우 (`GPR → CSR`):** 직전 ALU 명령어나 Load 명령어가 생성한 `rd` 값을 CSR 명령어가 소스 피연산자(`rs1`)로 참조하는 경우(`ALU → CSR`, `LW → CSR`).
2. **CSR이 RAW의 생산자(Producer)인 경우 (`CSR → GPR`):** CSR 명령어가 기존 CSR 값을 읽어 `rd`에 기록하고, 직후의 ALU·Branch·Load·Store 명령어가 해당 `rd`를 참조하는 경우(`CSR → ALU`, `CSR → Branch` 등).

이 두 방향의 의존성을 해결할 때 기존 ALU 데이터 경로를 경유할지 별도 파이프라인 경로를 둘지, 그리고 정지(Stall) 사이클이 얼마나 필요한지 결정한다.

### 2. 요구사항 및 제약조건

- ADR-003의 포워딩 우선순위(EX/MEM→EX 우선, MEM/WB→EX 차순위, WB→ID 우회)와 ADR-004의 Load-use 1사이클 정지 규칙을 그대로 유지하고 확장해야 한다.
- CSR 명령어가 `rs1`을 사용할 때만 최신 값을 반영하며, 즉시값형(`CSRRWI`, `CSRRSI`, `CSRRCI`)은 `zimm[4:0]`을 사용한다.
- 일반 ALU의 임계 경로(Critical Path)와 제어 신호 복잡도를 늘리지 않아야 한다.

### 3. 대안 비교

#### 3.1 CSR이 RAW의 소비자일 때 (`GPR → CSR` 피연산자 전달 경로)

| 비교 항목 | 대안 A: EX 단계 ALU 경유 (`rs1 + 0`) | 대안 B: WB 단계에 별도 포워딩 유닛 배치 | **대안 C: EX 포워딩 출력 탭(Tap) + 전용 파이프라인 경로 (선택)** |
| :--- | :--- | :--- | :--- |
| **전달 방식** | ALU에서 `rs1 + 0`을 계산해 기존 `AluData` 레지스터로 WB까지 전달 | `rs1` 주소를 WB까지 보내 WB에서 최신 값을 비교·선택 | **EX 단계 포워딩 MUX 출력을 별도 32b 레지스터로 캡처해 WB까지 전달** |
| **추가 하드웨어 비용** | **0 FF** (기존 `AluData` 32b × 2단 공유), 단 ALU 제어 로직 결합 | 주소 전달 10 FF + WB 전용 비교기·MUX 추가 | **64 FF** (EX/MEM 32b + MEM/WB 32b 전용 레지스터), 비교기·MUX 추가 **0개** |
| **`ALU → CSR` 정지 사이클** | 0사이클 (EX 포워딩) | 0사이클 | **0사이클** (기존 EX/MEM→EX 및 MEM/WB→EX 포워딩 그대로 재사용) |
| **`LW → CSR` 정지 사이클** | 1사이클 (기존 Load-use 동일) | 0사이클 가능하나 WB 제어 복잡 | **1사이클** (기존 Load-use 검출 조건으로 그대로 처리) |
| **제어 결합도 및 위험** | 즉시값(`zimm`)과 `rs1`을 동시에 다뤄야 할 때 ALU 입력 MUX와 충돌 | 이미 완료되어 파이프라인을 빠져나간 명령어의 값을 WB에서 추적 불가 | **ALU 제어와 완전히 독립**, 기존 EX 포워딩·해저드 로직 100% 재사용 |

#### 3.2 CSR이 RAW의 생산자일 때 (`CSR → GPR`, 예: `CSR → ALU/Branch`)

| 비교 항목 | 대안 1: Load-use 조건에 `WB_CSR` 추가 (1사이클 정지 + MEM/WB→EX 포워딩) | **대안 2: Load-use(`WB_CSR`) + CSR 파이프라인 직렬화(3사이클 보류) 결합 (선택)** |
| :--- | :--- | :--- |
| **동작 방식** | CSR을 Load와 동일하게 취급해 ID/EX 단계에서 1사이클 정지 후 MEM/WB에서 포워딩 | ADR-006의 3사이클 직렬화 보류와 `WB_CSR` 의존성 검출을 함께 적용 |
| **정지(버블) 사이클** | 1사이클 (단, WB에서 읽은 CSR 값을 EX로 보내는 긴 조합논리 우회 경로 발생) | **3사이클** (CSR이 WB를 마칠 때까지 후속 명령 인출 보류) |
| **WB→EX 임계 경로 영향** | `CSR 읽기(조합) → WB MUX → EX 포워딩 MUX → ALU/분기 비교기`가 한 사이클에 직결되어 Fmax 저하 | CSR이 WB에서 레지스터 파일에 기록을 마친 뒤 후속 명령이 진행하므로 **긴 WB→EX 조합 경로가 활성화되지 않음** |

#### 3.3 시나리오별 타이밍 비교

##### 시나리오 1: `LW → CSR` (CSR이 소비자 — 1사이클 정지 후 EX 포워딩 캡처)

| 명령어 \ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 | C7 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `lw x5, 0(x1)` | IF | ID | EX | MEM | WB (`x5` 확정) | | |
| `csrrw x6, mscratch, x5` | | IF | ID (Load-use 정지) | ID 진행 | EX (**MEM/WB→EX 우회값 캡처**) | MEM | WB (CSR 갱신) |
| 소비 사이클 | | | **+1사이클 대기** | | | | |

`lw`의 결과는 MEM 종료 후(C5)에 준비되므로, `csrrw`를 C3에서 1사이클 보류(ID/EX에 버블 1개 삽입)한 뒤 C5의 EX 단계에서 `MEM/WB→EX` 포워딩 경로로 `x5`를 캡처하여 전용 파이프라인 레지스터에 담아 WB로 보낸다. (`ALU → CSR`의 경우에는 정지 없이 **0사이클**에 `EX/MEM→EX` 포워딩 값을 즉시 캡처한다.)

##### 시나리오 2: `CSR → Branch/ALU` (CSR이 생산자 — 직렬화 보류 후 안전 소비)

| 명령어 \ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 | C7 | C8 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `csrrs x5, mip, x0` | IF | ID | EX | MEM | WB (`x5`에 CSR 값 기록) | | | |
| 직렬화 대기 | | IF | × (버블 1) | × (버블 2) | × (버블 3) | | | |
| `beq x5, x0, label` | | | PC 정지 | PC 정지 | PC 정지 | IF | ID (`x5` 읽기) | EX (분기 판정) |

### 4. 결정 및 근거

- **선택:**
  1. **소비자 경로(`GPR → CSR`):** 대안 C — EX 단계의 기존 포워딩 MUX 출력(`wAluRs1_Fwd`)을 탭(Tap)하여 별도 32비트 파이프라인 레지스터(`rEX_MEM_CsrSrc`, `rMEM_WB_CsrSrc` 총 **64 FF**)를 통해 WB 단계 CSR 연산기(`CsrOperation`)로 전달한다(즉시값형은 `rID_EX_Imm`을 `rEX_MEM_Imm` → `rMEM_WB_Imm`으로 전달하여 하위 5비트 `rMEM_WB_Imm[4:0]`을 `iZimm`으로 공급).
  2. **해저드 정지 정책:** `ALU → CSR`은 **0사이클 정지**(EX 포워딩), `LW → CSR`은 기존 Load-use 로직을 그대로 사용하여 **1사이클 정지**, `CSR → GPR(ALU/Branch/Store)`은 Load-use 조건(`WB_CSR`)과 ADR-006의 **3사이클 직렬화 보류**를 결합해 해결한다.
- **근거:**
  1. 64 FF만 추가하면 기존 포워딩 유닛(ADR-003)과 Load-use 해저드 유닛(ADR-004)의 비교기·제어 로직을 수정 없이 100% 재사용할 수 있으며, ALU 제어 경로와 CSR 경로가 완전히 분리되어 설계 오류 가능성을 줄인다.
  2. CSR 반환값(`WB_CSR`)이 WB의 CSR 조합논리 읽기부터 EX의 ALU/분기 비교기까지 한 사이클에 관통하는 긴 타이밍 경로를 직렬화 보류로 차단하여 클록 주파수(Fmax) 저하를 막는다.
- **감수 사항:** EX/MEM과 MEM/WB 단계에 `rs1` 전달용 64 FF가 추가되며, `LW → CSR` 실행 시 1사이클의 Load-use 정지와 3사이클의 CSR 직렬화 대기가 순차 적용된다.

### 5. 결과 및 후속 결정

- **검증 항목:** `ADD → CSRRW`(0사이클 정지), `LW → CSRRW`(1사이클 Load-use 정지), `CSRRS → BEQ` 및 `CSRRS → ADD`(3사이클 직렬화 후 최신 `rd` 반영) 지향 테스트 수행
- **예외 및 인터럽트와의 상호작용:** CSR 직렬화 정지 중 분기 플러시나 트랩 플러시가 발생할 때의 우선순위 정의 (ADR-011)
