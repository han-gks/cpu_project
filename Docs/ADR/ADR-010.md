# [ADR-010] 동기 예외(Exception) 및 MRET 처리 방식과 WB 커밋(Commit) 타이밍

- **작성일자:** 2026-11-02
- **작성자 / 리뷰어:** 한대규/장병옥, 정현재
- **상태:** 승인됨 (Accepted)
- **영향 범위:** 예외 해독(`ECALL`, 불법 명령어) 및 `MRET` 제어, 단계별 순차 Flush, WB 단계 트랩 확정

---

### 1. 배경 및 문제 정의

동기 예외(Synchronous Exception — 불법 명령어 `Illegal Instruction`, 환경 호출 `ECALL`)와 트랩 복귀 명령어(`MRET`)는 비동기 인터럽트(ADR-009)와 달리 **파이프라인의 특정 명령어 자체에서 발생**한다.

5단계 파이프라인에서 명령어 해독 단계(ID)에서 예외나 `MRET`이 검출되었을 때, 그보다 앞선 단계(EX, MEM, WB)에는 아직 완료되지 않은 **더 오래된(선행) 명령어 최대 3개**가 실행 중이고, 뒷단계(IF)에는 **더 젊은(후속) 명령어**가 인출되고 있다. 앞선 명령어는 모두 정상 완료시키고 예외 명령어 자신과 후속 명령어의 부작용만 정확히 차단하는(Precise Exception) 타이밍을 결정해야 한다.

### 2. 요구사항 및 제약조건

- 예외를 일으킨 명령어보다 프로그램 순서상 앞선 명령어들(EX, MEM, WB에 위치한 명령어)은 레지스터·메모리·CSR 쓰기를 100% 완료해야 한다.
- 예외를 일으킨 명령어 자신과 그 뒤를 따르는 젊은 명령어들은 어떠한 건축적 상태(GPR, Data Memory, CSR)도 변경해서는 안 된다.
- 예외 진입 시 `mepc`에는 **예외를 발생시킨 바로 그 명령어의 PC**가 저장되어야 하며, `mcause`에는 동기 예외 원인 코드(`Illegal Instruction = 2`, `ECALL from M-mode = 11`)가 기록되어야 한다.
- `MRET` 실행 시에는 앞선 명령어(예: 핸들러 마지막의 `mepc`/`mstatus` 복원 CSR 명령어나 스택 복구 명령어)가 모두 완료된 뒤 `PC <= mepc` 및 `mstatus` 복원이 이루어져야 한다.

### 3. 대안 비교

| 비교 항목 | 대안 A: 감지 단계(ID)에서 즉시 트랩 진입 | 대안 B: 예외 플래그 WB 전파 + WB 도달 시 일괄 Flush | **대안 C: 예외 플래그 WB 전파 + 후속 명령어 단계별 순차 Flush + WB 커밋 (선택)** |
| :--- | :--- | :--- | :--- |
| **핵심 메커니즘** | ID에서 예외 감지 즉시 CSR 갱신 및 `mtvec`으로 분기 | 예외 정보를 WB까지 보내고, WB 도달 순간에 앞단(IF~MEM)을 한 번에 Flush | **ID에서 자신 부작용 차단 후 WB까지 전파하되, 이동 중 뒤따르는 젊은 단계들을 매 사이클 순차 Flush하고 WB에서 최종 커밋** |
| **선행(오래된) 명령어 보존** | EX·MEM의 선행 명령어를 별도 드레인하지 않으면 상태 불일치 발생 | 자연스럽게 WB까지 먼저 완료됨 | **자연스럽게 WB까지 먼저 완료됨 (100% 보장)** |
| **후속(젊은) 명령어의 부작용 방지** | 즉시 차단 가능 | 예외 명령어가 WB에 도달하기 전 2사이클 동안 **뒤따르는 젊은 명령어가 EX(분기)·MEM(Store)에 진입해 부작용을 일으킬 위험** 있음 | **예외 명령어 뒤의 단계(IF/ID → ID/EX → EX/MEM)를 매 사이클 즉시 Flush하여 후속 명령어의 EX·MEM 진입 자체를 원천 차단** |
| **ID 감지부터 트랩 분기까지 소비 사이클** | 1사이클 (단, 선행 명령어 오염 문제로 추가 대기 필요) | **3사이클 전파 + 1사이클 분기 (총 4사이클 버블)** | **3사이클 전파 + 1사이클 분기 (총 4사이클 버블)** |
| **추가 파이프라인 FF** | 선행 명령어 보호용 복잡한 제어 필요 | 단계당 `Exc(1b)+Mret(1b)+Cause(4b) = 6 FF` × 3단 = **18 FF** | 단계당 `Exc(1b)+Mret(1b)+Cause(4b) = 6 FF` × 3단 = **18 FF** (대안 B와 동일) |

#### 대안 B와 대안 C의 결정적 차이 (후속 명령어 조기 차단)

만약 예외 명령어(`E`)가 WB에 도달할 때까지 기다렸다가 한 번에 Flush(대안 B)하면, `E`가 MEM에 있을 때 바로 뒤의 젊은 명령어(`Y1`)는 EX에서 분기를 일으키거나, `E`가 WB에 도달하는 사이클에 `Y1`이 MEM 단계에 진입해 잘못된 메모리 접근을 시도할 수 있다. 반면 **대안 C(순차 Flush)**는 `E`가 한 단계 전진할 때마다 그 뒤를 즉시 버블로 채우므로 후속 명령어가 EX 단계조차 밟지 못한다.

#### 선택안(대안 C)의 단계별 Flush 마스크 및 사이클 타이밍

표기: `O1, O2`는 예외 명령어보다 앞선 오래된 명령어, `E`는 예외 명령어(`ECALL`/불법 명령어/`MRET`), `Y1, Y2`는 뒤따라 인출된 젊은 명령어, `H1`은 트랩 핸들러(`mtvec` 또는 `mepc`)의 첫 명령어다. Flush 마스크는 `{IF/ID, ID/EX, EX/MEM, MEM/WB}` 4비트로 정의한다.

| 명령어 / 제어 \ 사이클 | C1 | C2 (ID 해독) | C3 (`E`가 EX) | C4 (`E`가 MEM) | C5 (`E`가 WB 커밋) | C6 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `O1` (선행 명령어 1) | EX | MEM | **WB (정상 완료)** | | | |
| `O2` (선행 명령어 2) | ID | EX | MEM | **WB (정상 완료)** | | |
| `E` (`ecall` / `mret`) | IF | **ID (예외 감지·부작용=0)** | EX (전파) | MEM (전파) | **WB (CSR 갱신·PC 전환)** | |
| `Y1` (후속 젊은 명령어 1) | | IF | ID | **× (ID/EX Flush로 소멸)** | | |
| `Y2` (후속 젊은 명령어 2) | | | IF (PC 정지) | **× (IF/ID Flush로 소멸)** | | |
| `H1` (`mtvec` / `mepc`) | | | | | | **IF (핸들러 인출)** |
| **단계별 `TrapFlush` 마스크** | `4'b0000` | `4'b0000` | **`4'b1100` (`ID/EX` 예외)** | **`4'b1110` (`EX/MEM` 예외)** | **`4'b1111` (`MEM/WB` 커밋)** | `4'b0000` |

1. **C2 (ID 단계):** `E`가 해독되면 즉시 자신의 `RegWrEn`, `MemValid`, `MemWrEn`, `CsrEn`, `BranchEn`을 모두 `0`으로 억제하고, `Exc=1`과 `Cause`(4비트)만 ID/EX로 넘긴다.
2. **C3 (`E`가 ID/EX에 위치):** `TrapFlush = 4'b1100`을 구동해 PC를 정지하고 `IF/ID`와 `ID/EX`를 플러시한다. 이로써 뒤따르던 `Y1`은 EX로 넘어가지 못하고 즉시 제거된다. 한편 선행 명령어 `O1`은 WB에서 정상 완료된다.
3. **C4 (`E`가 EX/MEM에 위치):** `TrapFlush = 4'b1110`으로 `IF/ID`, `ID/EX`, `EX/MEM`을 플러시하여 `E` 뒤쪽을 완전히 비운 상태로 유지한다. 선행 명령어 `O2`는 WB에서 정상 완료된다.
4. **C5 (`E`가 MEM/WB에 도달 — 원자적 커밋):** 모든 선행 명령어(`O1, O2`)가 완료되었으므로, `TrapFlush = 4'b1111`과 함께 1사이클 만에 `mepc <= MEM_WB_PC`, `mcause <= Cause`, `mstatus` 갱신 및 `PC <= mtvec`(`MRET`이면 `PC <= mepc`) 전환을 확정한다.

### 4. 결정 및 근거

- **선택:** 대안 C — 동기 예외(`ECALL`, 불법 명령어) 및 `MRET`은 ID 단계에서 감지 즉시 해당 명령어의 부작용을 차단하고 예외 정보를 파이프라인으로 전파하며, 이동 중 뒤따르는 젊은 단계들을 순차적으로 Flush(`4'b1100` → `4'b1110` → `4'b1111`)한 뒤 **WB 단계에서 원자적으로 트랩을 확정(Commit)**한다.
- **근거:**
  1. **완벽한 Precise Exception 보장:** 예외 명령어가 WB에 도달하기까지 **3사이클** 동안 앞선 명령어들이 자연스럽게 WB를 거쳐 완료되므로 별도의 대기 카운터 없이 선행 명령어 완료가 보장된다.
  2. **젊은 명령어 부작용 원천 차단:** 단계별 순차 Flush(`4'b1100` → `4'b1110`)를 통해 예외 명령어 뒤의 젊은 명령어가 EX(분기 판정)나 MEM(메모리 쓰기) 단계에 절대 진입하지 못한다.
  3. **낮은 하드웨어 오버헤드:** 파이프라인 단계당 6비트(총 **18 FF**)와 3단계 우선순위 디코더만으로 동기 예외와 `MRET`을 단일 경로에서 일관되게 처리할 수 있다.
- **감수 사항:** 예외 감지(ID) 시점부터 트랩 핸들러 첫 명령어 인출까지 **고정 4사이클의 파이프라인 버블 페널티**(전파 3사이클 + 분기 전환 1사이클)가 소비된다.

### 5. 결과 및 후속 결정

- **향후 MEM 단계 예외 확장성:** 향후 정렬 오류(Misaligned Access)나 버스 오류(Access Fault) 등 MEM 단계 예외를 추가할 경우에도 동일한 `MEM/WB` 예외 플래그에 합류시켜 같은 WB 커밋 경로로 처리할 수 있다.
- **비동기 인터럽트와의 충돌 중재:** 동기 예외 전파 중 비동기 인터럽트가 동시에 발생할 때의 우선순위 규칙은 ADR-011에서 통합 정의한다.
