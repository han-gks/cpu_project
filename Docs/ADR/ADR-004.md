# [ADR-004] Load-use 해저드 정지 및 버블 삽입

- **작성일자:** 2026-10-29
- **작성자 / 리뷰어:** 한대규/장병옥, 정현재
- **상태:** 승인됨 (Accepted)
- **영향 범위:** PC 갱신, IF/ID 유지·무효화, ID/EX 제어, load 결과 소비

---

### 1. 배경 및 결정

load 명령의 데이터는 메모리 접근 뒤에 준비되므로, 바로 다음 명령이 해당 값을 EX 단계에서 요구하면 일반 ALU 포워딩만으로는 제때 전달할 수 없다. 정지 동안 종속 명령을 보존하고, 생산 명령은 진행시키며, 빈 실행 슬롯(버블)을 넣어야 한다.

**선택안:** load-use가 검출된 사이클에 PC와 IF/ID를 보류하고 ID/EX를 버블로 만든다. 다음 사이클에 소비 명령을 진행시키고 MEM/WB→EX 포워딩으로 load 데이터를 전달한다. 이는 종속 명령을 유지하면서 제어 동작을 명시적으로 구분하는 방식이다.

### 2. 대안 비교

| 대안 | PC | IF/ID | ID/EX | 장점 | 비용 및 주의점 |
| :--- | :--- | :--- | :--- | :--- | :--- |

### 3. 선택안 사이클 예시

`L`은 load, `C`는 바로 뒤의 종속 소비 명령, `B`는 버블이다. 한 사이클 대기 후 소비 명령은 MEM/WB의 load 결과를 EX에서 받는다.

| 명령어/상태 \ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 | C7 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| L: `lw x5,...` | IF | ID | EX | MEM | WB | | |
| C: `add x6,x5,...` | | IF | ID 보류 | ID 진행 | EX (MEM/WB 우회) | MEM | WB |
| 다음 명령 | | | IF 보류 | IF | ID | EX | MEM |
| ID/EX 슬롯 | | | B 삽입 | C | 다음 명령 | | |
| PC | +4 | +4 | 보류 | +4 | +4 | +4 | +4 |

보류 사이클 종료 때 load는 EX/MEM으로 진행하고 ID/EX에는 버블이 들어간다. 소비 명령은 IF/ID에 그대로 남아 다음 사이클 ID에서 다시 제어되고, 이후 EX에서 MEM/WB 결과를 받는다.

#### 대안 타이밍 비교

| 명령어/대안 \ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 | C7 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **포워딩만, 정지 없음** ||||||||
| L: `lw x5,...` | IF | ID | EX | MEM | WB | | |
| C: `add x6,x5,...` | | IF | ID | EX (값 미준비) | MEM | WB | |
| **PC·IF/ID 보류, ID/EX 버블 (선택)** ||||||||
| L: `lw x5,...` | IF | ID | EX | MEM | WB | | |
| C: `add x6,x5,...` | | IF | ID 보류 | ID 진행 | EX (WB 우회) | MEM | WB |
| 다음 명령 | | | IF 보류 | IF | ID | EX | MEM |
| **PC 정지, IF/ID 플러시 후 소비 명령 재인출** ||||||||
| L: `lw x5,...` | IF | ID | EX | MEM | WB | | |
| C: `add x6,x5,...` | | IF | ID 검출·플러시 | IF 재인출 | ID (WB→ID 우회) | EX | MEM |
| 다음 명령 | | | IF 보류 | | IF | ID | EX |
| ID/EX 슬롯 | | | 버블 | 버블 | C | 다음 명령 | |

재인출 대안은 종속 명령의 PC를 보존해 다시 IF에 공급한다고 가정한다. 추가 재인출 때문에 선택안보다 지연이 더 길다. 이 주소 보존/재생(replay) 제어 없이 IF/ID만 플러시하면 종속 명령은 복구되지 않는다.
### 4. 플러시 방식과의 차이

PC 정지 + IF/ID 플러시 + ID/EX 버블을 선택하려면, IF/ID의 소비 명령을 버린 뒤 동일한 명령을 다시 가져올 수 있어야 한다. PC가 이미 소비 명령 다음 주소를 가리키는 구조라면 단순 플러시로는 소비 명령을 잃는다. 따라서 재인출 주소 보존, PC 보정 또는 별도 replay 제어를 함께 정해야 한다.

반면 IF/ID 보류 방식은 소비 명령을 파이프라인 레지스터에 그대로 보존하므로 재인출이 필요 없다. `stall`은 해당 레지스터의 값 유지, `flush`는 유효하지 않은 명령/제어 상태로 교체하는 동작으로 구분한다.

### 5. 검출 조건과 우선순위

- load가 목적 레지스터에 유효한 값을 쓰고, 다음 명령이 실제로 사용하는 rs1 또는 rs2와 목적지가 일치할 때만 정지한다.
- x0 목적지, 실제 소스가 아닌 명령 비트, 무효 명령은 의존성 검출에서 제외한다.
- **충돌 우선순위:** 분기 판정에서 taken이 나와 redirect/flush와 load-use stall이 같은 사이클에 동시에 요청되면 branch redirect/flush가 우선한다(override). 이때 PC는 분기 목표 주소로 갱신하고, IF/ID와 ID/EX를 플러시하며, PC/IF/ID 정지는 적용하지 않는다. 따라서 잘못된 경로의 명령이 stall로 보존되지 않는다. 두 요청이 동시에 나오는 경우에도 우선순위가 결정적으로 유지된다.

### 6. 검증

`lw→ALU`, `lw→branch`, `lw→store-data`, `lw→store-address` 및 독립 명령 뒤의 load 소비를 확인한다. 정지 횟수, 보존된 명령 순서, 버블의 레지스터·메모리 쓰기 비활성, 분기와 동시 발생하는 경우를 점검한다.
