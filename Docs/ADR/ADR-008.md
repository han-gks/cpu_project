# [ADR-008] CSR 레지스터 파일의 갱신 주체별 포트 구조 및 중재 방식

- **작성일자:** 2026-10-31
- **작성자 / 리뷰어:** 한대규/장병옥, 정현재
- **상태:** 승인됨 (Accepted)
- **영향 범위:** CSR 레지스터 파일 쓰기 포트 구조, 트랩 진입·복귀 시 상태 갱신 지연, 외부 인터럽트 감지 경로

---

### 1. 배경 및 문제 정의

일반 정수 레지스터 파일(GPR)은 WB 단계의 명령어 결과 하나만 기록하므로 단일 쓰기 포트(주소 5비트 + 데이터 32비트)로 충분하다. 그러나 CSR 레지스터 파일은 **① WB 단계의 일반 CSR 명령어(소프트웨어)**뿐만 아니라 **② 트랩(예외·인터럽트) 진입 및 `MRET` 복귀 시의 하드웨어 제어 로직**, 그리고 **③ 외부 인터럽트 컨트롤러(CLINT·PLIC)의 실시간 대기(Pending) 신호**라는 세 가지 서로 다른 주체에 의해 갱신된다.

특히 트랩 진입 시에는 `mstatus`, `mepc`, `mcause`, `mtval` 4개의 CSR이 동시에 갱신되어야 하므로, CSR 레지스터 파일의 쓰기 포트를 어떻게 구성하고 충돌 시 어떤 우선순위를 부여할지 사전에 결정해야 한다.

### 2. 요구사항 및 제약조건

- 트랩 진입 시 `mstatus`(`MPIE <= MIE`, `MIE <= 0`), `mepc`, `mcause`, `mtval`이 프로그램 순서상 원자적으로(Atomically) 갱신되어야 한다.
- `MRET` 실행 시에는 `mstatus`(`MIE <= MPIE`, `MPIE <= 1`)만 갱신하고, 기존의 `mepc`, `mcause`, `mtval` 값은 훼손하지 않고 보존해야 한다.
- 외부 인터럽트 대기 상태(`mip`)는 파이프라인에 CSR 명령어가 없거나 파이프라인이 정지(Stall)된 동안에도 지연 없이 반영되어야 한다.
- 불필요한 멀티플렉서(MUX) 증가를 억제하기 위해 꼭 필요한 레지스터에만 다중 쓰기 경로를 부여한다.

### 3. 대안 비교

| 비교 항목 | 대안 A: 단일 주소·데이터 쓰기 포트 시분할 공유 | 대안 B: 전체 8종 CSR 완전 다중 포트화 | **대안 C: 갱신 주체별 3계층 분리 구조 (선택)** |
| :--- | :--- | :--- | :--- |
| **포트 구조** | 12b 주소 + 32b 데이터 포트 1개를 SW와 Trap HW가 시분할 사용 | 8종 모든 CSR에 SW 쓰기와 HW 쓰기 MUX를 각각 배치 | **① SW 전용(3종) / ② SW+Trap 공유(4종) / ③ HW 직결(1종) 분리** |
| **트랩 진입 시 CSR 갱신 사이클** | **4사이클 소요** (`mstatus`→`mepc`→`mcause`→`mtval` 순차 기록) | **1사이클** (동시 병렬 갱신) | **1사이클** (공유 4종 CSR 동시 병렬 갱신) |
| **추가 제어 복잡도** | 4사이클 시퀀서(FSM) 및 그 동안 파이프라인 강제 정지 필요 | FSM 불필요; 단 HW가 쓰지 않는 CSR에도 MUX 낭비 | **FSM 불필요**; 단일 사이클 원자적 트랩 진입 가능 |
| **`mip` 반영 지연** | WB 포트 경유 시 최소 **1~4사이클 지연** (Stall 시 갱신 불가) | 1사이클 (FF 거침) | **0사이클** (CLINT/PLIC 신호 조합논리 Wire 직결, 32 FF 절감) |
| **쓰기 선택 MUX 규모** | 32b 2:1 MUX × 1개 + 주소 MUX | 32b 2:1 MUX × 8개 (256b) | **32b 2:1 MUX × 4개 (128b)** (공유 4종에만 배치) |

#### 선택안(대안 C)의 CSR 계층별 구조 및 동작

| 분류 | 대상 CSR (개수) | 물리 저장소 | 쓰기 포트 및 우선순위 규칙 |
| :--- | :--- | :--- | :--- |
| **1. SW + Trap HW 공유** | `mstatus`, `mepc`, `mcause`, `mtval` (4종) | 4 × 32b FF (WARL 마스킹) | **1순위:** Trap 하드웨어 병렬 쓰기 (`TrapWrEn=1`, 단 `MRET` 시 `mepc/mcause/mtval`은 쓰기 차단하여 값 보존)<br>**2순위:** WB 단계 CSR 명령어 주소 일치 쓰기 (`CsrWrEn=1`) |
| **2. SW 전용 (SW-Only)** | `mie`, `mtvec`, `mscratch` (3종) | 3 × 32b FF (WARL 마스킹) | WB 단계 CSR 명령어 주소 일치 쓰기 포트만 연결 (Trap 하드웨어 포트 연결 없음) |
| **3. HW 직결 (HW-Only)** | `mip` (1종) | **0 FF (조합논리 Wire)** | `{20'b0, MEIP, 3'b0, MTIP, 3'b0, MSIP, 3'b0}` 형태로 외부 인터럽트 신호를 직결 (SW 쓰기 무시) |

| 구분 \ 사이클 | C1 (트랩 확정) | C2 | C3 | C4 | C5 (핸들러 첫 명령어) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **대안 A (단일 포트 시분할)** | `mstatus` 기록 | `mepc` 기록 | `mcause` 기록 | `mtval` 기록 | `mtvec` 인출 시작 (**4사이클 소요**) |
| **대안 C (3계층 분리, 선택)** | **`mstatus·mepc·mcause·mtval` 동시 기록 + PC=`mtvec`** | **`mtvec` 인출 시작 (1사이클 완료)** | ID | EX | MEM |

### 4. 결정 및 근거

- **선택:** 대안 C — CSR 레지스터 파일을 갱신 주체에 따라 **SW+Trap 공유(4종), SW 전용(3종), HW 직결(1종)의 3계층으로 분리**하고, 공유 CSR에서는 Trap 하드웨어 병렬 쓰기에 최우선 순위를 부여한다.
- **근거:**
  1. **트랩 진입 지연 3사이클 단축:** 단일 쓰기 포트(대안 A)를 쓰면 4개의 CSR을 기록하느라 트랩 진입마다 4사이클과 별도 FSM이 소비되지만, 공유 4종 CSR에 Trap 전용 병렬 쓰기 포트를 두면 **1사이클 만에 원자적으로 트랩 상태를 확정**할 수 있다.
  2. **실시간 인터럽트 감시 및 면적 절감:** `mip`를 플립플롭 없이 외부 신호 조합논리 Wire로 구성하여 32 FF를 절약하고, 파이프라인 정지 여부와 무관하게 **0사이클 지연**으로 인터럽트 대기 상태를 트랩 제어기에 전달한다.
  3. **`MRET` 상태 보존:** 공유 CSR 쓰기 조건에서 `MRET` 신호를 구분하여 `mstatus`만 1사이클에 복원하고 `mepc`, `mcause`, `mtval`은 덮어쓰지 않도록 간결하게 제어할 수 있다.
- **감수 사항:** 트랩 제어기와 CSR 레지스터 파일 사이에 4개의 32비트 쓰기 버스(128비트)와 5개의 32비트 상시 읽기 버스(`mstatus`, `mie`, `mip`, `mtvec`, `mepc` — 160비트) 배선이 추가된다.

### 5. 결과 및 후속 결정

- **읽기 타이밍:** CSR 읽기는 WB 단계의 명령어 읽기(`CsrRdData`)와 트랩 제어기의 상시 상태 감시 모두 조합논리(0사이클 지연)로 출력한다.
- **트랩 제어기 연동:** 본 포트 구조를 기반으로 비동기 인터럽트(ADR-009)와 동기 예외(ADR-010)의 정확한 트랩 확정 시점을 정의한다.
