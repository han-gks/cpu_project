# [ADR-003] 데이터 포워딩 경로와 우선순위

- **작성일자:** 2026-10-29
- **작성자 / 리뷰어:** 한대규/장병옥, 정현재
- **상태:** 승인됨 (Accepted)
- **영향 범위:** EX 피연산자 선택, 레지스터 파일 읽기, RAW 데이터 의존성

---

### 1. 배경 및 결정

생산 명령어의 결과가 레지스터 파일에 기록되기 전 소비 명령어가 값을 읽을 수 있다. 포워딩은 결과를 레지스터 파일 기록 시점까지 기다리지 않고 생산 단계에서 소비 단계로 전달하는 방법이다.

**선택안:** EX/MEM 결과를 우선하고 MEM/WB write-back 결과를 다음 우선순위로 EX 입력에 우회한다. 레지스터 파일은 같은 사이클의 WB 기록 대 ID 읽기 충돌에 대해 WB→ID 우회를 제공한다. 이 포워딩으로 해결되지 않는 load-use 의존성은 별도 해저드 정책으로 처리한다.

### 2. 대안 비교

| 경로/정책 | 전달 시점 | 장점 | 비용 및 주의점 |
| :--- | :--- | :--- | :--- |
| 포워딩 없이 대기 | 레지스터 파일 기록 뒤 소비 | 데이터 경로 단순 | 의존성마다 여러 사이클 대기 가능 |
| WB→ID | WB 결과를 ID 읽기 포트로 우회 | 같은 사이클 읽기/쓰기 충돌 해결 | EX에서 필요한 결과에 대한 대체 경로가 아님 |
| EX/MEM→EX | 직전 생산자의 EX/MEM 값을 EX 피연산자로 전달 | ALU 결과 의존성을 대기 없이 처리 | 결과 MUX·비교 제어 추가; load 데이터에는 사용 불가 |
| MEM/WB→EX | WB 선택기 출력을 EX 피연산자로 전달 | 한 단계 더 오래된 의존성 처리; load 결과도 전달 가능 | 결과 MUX·비교 제어 추가 |
| EX/MEM 및 MEM/WB→ID | 최신 값을 ID의 피연산자·분기 비교기로 전달 | 분기 판정 등 소비를 앞당길 수 있음 | ID 데이터 경로와 우선순위 제어 복잡성 증가 |

### 3. 선택 경로의 타이밍 예시

표기: `P`는 결과 생산 명령어, `C`는 그 결과를 소비하는 명령어. 사이클의 파이프라인 단계는 IF–ID–EX–MEM–WB다.

#### 직전 ALU 결과: EX/MEM→EX

| 명령어 \ 사이클 | C1 | C2 | C3 | C4 | C5 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| P: `add x5,...` | IF | ID | EX | MEM | WB |
| C: `sub x6,x5,...` | | IF | ID | EX (EX/MEM 우회) | MEM |

#### 두 단계 앞 ALU 결과: MEM/WB→EX

| 명령어 \ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| P: `add x5,...` | IF | ID | EX | MEM | WB | |
| 독립 명령 | | IF | ID | EX | MEM | WB |
| C: `sub x6,x5,...` | | | IF | ID | EX (WB 값 우회) | MEM |

#### 같은 사이클 WB 기록과 ID 읽기

| 사이클 | 생산 명령어 P | 소비 명령어 C | 우회 |
| :--- | :--- | :--- | :--- |
| C5 | WB: x5 기록 | ID: x5 읽기 | WB→ID |

같은 사이클의 레지스터 파일 쓰기와 읽기 포트 의미에 의존하지 않고, write-back 값을 읽기 출력에 직접 선택한다.

#### Load-use: 포워딩만으로 해결되지 않는 경우

| 명령어 \ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| P: `lw x5,...` | IF | ID | EX | MEM | WB | |
| C: `add x6,x5,...` | | IF | ID | ID 대기 | EX (MEM/WB 우회) | MEM |

Load 데이터는 MEM에서 준비되어야 하므로, 소비 명령이 바로 다음 사이클 EX로 가면 EX/MEM에는 주소만 있다. 한 사이클을 대기시킨 뒤 MEM/WB 값으로 전달한다. 정확한 정지 및 버블 제어는 ADR-004에서 결정한다.

#### 대안: 포워딩 없이 WB까지 대기

| 명령어 \ 사이클 | C1 | C2 | C3 | C4 | C5 | C6 | C7 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| P: `add x5,...` | IF | ID | EX | MEM | WB | | |
| C: `sub x6,x5,...` | | IF | ID 대기 | ID 대기 | ID 대기 | ID 최신 값 읽기 | EX |

레지스터 파일 쓰기 이후에만 소비자가 값을 읽도록 보수적으로 구성하면, RAW 의존성마다 여러 정지 사이클이 필요할 수 있다. WB→ID 같은 사이클 우회가 있으면 대기 횟수는 줄어들 수 있다.

#### 대안: ID 단계로 결과 우회

| 명령어 \ 사이클 | C1 | C2 | C3 | C4 | C5 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| P: `add x5,...` | IF | ID | EX | MEM | WB |
| B: `beq x5,x0,...` | | IF | ID (EX/MEM 값 비교 입력으로 우회) | EX | MEM |

ID에서 분기 피연산자에 최신 결과를 우회하면 분기를 일찍 판정할 수 있다. 다만 결과가 같은 사이클에 아직 계산 중이거나 load 결과처럼 늦게 준비되는 경우는 별도 스톨/우회가 필요하다. 분기 판정 단계 선택은 ADR-002에서 다룬다.
### 4. 우선순위와 적용 범위

- 같은 목적 레지스터에 여러 미완료 생산자가 있으면 가장 최신 결과를 선택한다: EX/MEM 우선, 그다음 MEM/WB.
- x0은 항상 0이므로 목적 레지스터가 x0인 생산자는 포워딩하지 않는다.
- 포워딩 대상은 실제로 해당 소스 레지스터를 사용하는 명령어의 피연산자로 한정한다.
- ALU 연산, EX 단계 분기 비교, store 데이터 등 소비 위치별 경로를 정의한다. 각 경로가 필요한지 명령어별로 확인한다.

### 5. 결과 및 검증

연속 쓰기 후 소비, EX/MEM과 MEM/WB가 동일 목적지를 갖는 경우, load 결과 소비, 분기 피연산자 및 store 데이터 의존성을 검증한다. 정량적인 지연·주파수 효과는 구현 및 측정 조건을 기록한 뒤 평가한다.
