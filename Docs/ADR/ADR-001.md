# [ADR-001] 파이프라인 CPU 채택

- **작성일자:** 2026-10-29
- **작성자 / 리뷰어:** 한대규/장병옥, 정현재
- **상태:** 승인됨 (Accepted)
- **영향 범위:** CPU 마이크로아키텍처 및 후속 제어·검증 설계

---

### 1. 배경 및 문제 정의

싱글사이클은 명령어 하나를 한 사이클에 완료하지만, 가장 긴 명령어 경로가 전체 클록 주기를 결정한다. 멀티사이클은 작업을 여러 사이클로 나누고 하드웨어를 재사용하지만, 한 번에 한 명령어를 처리한다. 파이프라인은 명령어를 여러 단계로 나누어 겹쳐 실행함으로써 처리량을 높인다.

파이프라인의 교육적 목표는 명령어 중첩, 성능과 복잡도의 교환 관계, 데이터·제어·구조 해저드의 원인과 처리 방법을 이해하는 것이다. 파이프라인 단계 수와 해저드 처리 정책은 후속 설계에서 정한다.

### 2. 요구사항 및 제약조건

- RV32I 명령어의 결과는 순차 실행 의미와 일치해야 한다.
- 단계 사이의 상태를 보존하고, 의존성·분기·자원 충돌을 올바르게 처리해야 한다.
- 단계 수, 예외·인터럽트 지원 범위 및 성능 목표는 미확정이다.
- 아래 수치는 고전적인 5단계 파이프라인을 참고한 **일반적인 교육용 추정치**다. 실제 구현의 측정값이 아니며, 타이밍 수치는 기재하지 않는다.

### 3. 대안 비교

| 항목 | 싱글사이클 | 멀티사이클 | 파이프라인 (5단계 예시) |
| :--- | :--- | :--- | :--- |
| 실행 방식 | 사이클당 명령어 1개 완료 | 명령어 하나를 여러 사이클에 처리 | 여러 명령어의 단계를 중첩 실행 |
| 일반적인 CPI | 1; 긴 클록 주기 | 약 3–5 | 이상적 조건에서 약 1; 해저드로 스톨 발생 |
| 처리량 | 기준; 최장 경로가 클록 주기를 결정 | 대략 3–5사이클당 명령어 1개 | 이상적으로 멀티사이클 대비 약 3–5배 |
| 추가 상태 | 파이프라인 상태 레지스터 거의 없음 | 중간 레지스터; 약 100–200 FF* | 파이프라인 레지스터; 약 350–400 FF* |
| 제어 복잡도 | 낮음 | FSM 및 단계 제어 | 해저드 검출, 포워딩, 스톨·플러시 |
| 교육 목표 | 기본 데이터패스 | 자원 재사용 및 제어 | 중첩 실행, 해저드, 성능 교환 관계 |

\* 대략적인 규모 비교를 위한 예시다. 파이프라인 레지스터는 단계 사이에 전달할 PC, 명령어 필드, 데이터 및 제어 정보를 포함한다고 가정한다. 레지스터 파일, 기본 PC/상태 레지스터, 구현별 추가 필드는 제외하거나 달라질 수 있다. 실제 FF 수는 데이터패스와 합성 결과로 확인한다.

- **싱글사이클:** 구조가 단순하지만 한 사이클에 긴 경로를 수용해야 한다.
- **멀티사이클:** 하드웨어를 재사용하고 경로를 나눌 수 있지만, 명령어당 여러 사이클과 순차 제어가 필요하다.
- **파이프라인:** 처리량을 높이고 단계 중첩을 학습할 수 있지만, 단계 레지스터와 해저드 제어·검증 비용이 추가된다.

### 4. 결정 및 근거

- **선택:** 파이프라인 CPU
- **근거:** 명령어 중첩으로 처리량을 높이는 구조를 구현하고, 해저드 처리와 그에 따른 성능·복잡도 교환 관계를 학습·검증한다.
- **감수 사항:** 추가 FF와 제어 로직이 필요하며, 스톨·플러시 상황을 포함한 검증 부담이 커진다. 정량적인 면적·타이밍 영향은 구현 후 측정한다.

### 5. 결과 및 후속 결정

- **데이터 해저드:** 포워딩 또는 스톨 정책 정의
- **제어 해저드:** 분기·점프 시 PC 갱신 및 플러시 정책 정의
- **구조 해저드:** 자원 분리·중재·스톨 중 처리 방식 정의
- **예외·인터럽트:** 지원 범위와 파이프라인 취소 규칙 결정
- **검증:** RV32I 결과와 레지스터·메모리 상태를 참조 모델과 비교하고, 해저드별 지향 테스트 수행
- **타이밍:** 합성·타이밍 분석 후 조건과 결과를 별도로 기록
